# Codex 浏览器超时：后台请求未走代理

2026-10-11，本机实测。开启 Clash TUN 后页面读取恢复；长期稳定性尚未验证。

## 关键证据

- 报错：`js execution timed out; kernel reset, rerun your request`，约 30 秒超时，右侧网页仍正常显示。
- 计时定位：后台请求 `https://chatgpt.com/backend-api/aura/site_status` 约 21 秒后失败；调试器初始化和页面执行各仅 1–6 毫秒。
- 系统代理开启时，Codex 主进程连接 `127.0.0.1:7897`，浏览器后台 `node_repl.exe` 仍直连，出现连接等待；其实际环境没有代理变量。
- 换节点后仍超时。开启 TUN 后，同一闲鱼搜索页读取 **1.32 秒**完成，页面脚本 **31 毫秒**读到 **30 条商品**。

这组对照强力支持：后台 OpenAI 请求未进入代理是主要原因。网页加载和工具后台请求路径不同，网页能打开不能排除网络问题。TUN 恢复了本次读取，不代表已验证接口返回或长期稳定性。

## 配置踩坑

- 修改插件缓存 `.mcp.json`：重启后新增代理变量消失。
- 修改另一个 `mcp_servers.node_repl`：不等于配置实际浏览器工具 `cua_repl`。
- 用户配置只写 `cua_repl.env`：本机报 `invalid transport`；完整启动定义可通过静态检查，但随后该启动项也消失，运行进程未拿到变量。**未确认移除来源，不能当作可靠的持久方案。**
- 配置查询成功不等于运行进程生效；JS 内核 reset 也不等于工具进程重启。

## 排查顺序

1. 查实际后台进程的代理环境和连接去向，不只看配置文件或系统代理。
2. 分别检查网页访问与后台 OpenAI 请求；用 TUN 做对照时复测同一页面。
3. 以真实读取结果和耗时验收。延长超时、匿名 HTTP 403 或节点延迟都不能证明修复。

首次消息反复重连另查：本机日志也出现节点入口连接超时和模型请求约每 15 秒重试，不应与浏览器后台直连混为一个问题。
