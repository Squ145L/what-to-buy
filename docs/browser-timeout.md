# `js execution timed out; kernel reset, rerun your request`

2026-10-11 定位。排查花了数小时，记下来省下一次。

## 症状

Codex 浏览器调用超时：

```text
js execution timed out; kernel reset, rerun your request
```

脚本内分阶段计时：

| 动作 | 耗时 |
|---|---|
| 新建标签页 | 0.1 s ✓ |
| 导航 | 0.2 s ✓ |
| **读取页面** | **20 s 超时** ✗ |

创建和导航秒回，只有"读取"挂。超时后内核 reset。

**把创建和读取拆成两次调用，不解决。**换个站读，同样超时。

## 已验证排除

先说走过哪两个错方向，免得重走：

- **不是工作流问题** —— 和 skill 的六步流程无关
- **不是 HTML 消息提取问题** —— 报错里不含任何页面级信息
- **不是"读取阶段的路由与回调"** —— 最初的错误方向，往这儿查了几小时

## 根因

**Codex 浏览器的网络环境和 Codex CLI 不是同一个。**

- Codex CLI → 走本地 Clash 代理（127.0.0.1:7897）
- Codex 浏览器 → **直连**

浏览器到不了站点，页面内容永远不来，"读取"就一直等到超时。

这也解释了为什么创建和导航是秒回的：**它们不等内容。**

## 判别

**看浏览器窗口：页面真的加载出来了吗？**

| 现象 | 结论 |
|---|---|
| 页面加载不出来 | 网络环境问题（本文） |
| 页面正常但读取仍超时 | 另找原因，本文不适用 |

## 待确认

上面"根因"一节是当前解释，但有一处没闭合，别当定论：

- **浏览器直连到底能通哪些站？** 闲鱼是**国内站**，大陆直连本该正常。
  如果直连打不开它，就得弄清这里的"直连"是哪种不通：
  不通外网？不通内网？还是浏览器压根没拿到可用网络配置？
- 怎么修：让浏览器也走代理，还是让 CLI 也直连？

判定方法：让浏览器开一个**已知可达**的页面对照。浏览器连普通页面都打不开，
才是真正的网络环境问题。
