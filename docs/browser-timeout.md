# `js execution timed out; kernel reset, rerun your request`

2026-10-11。排查数小时，**尚未闭合**。本文的"根因"改过一次，看的时候注意是哪一版。

## 症状

Codex 浏览器调用超时：

```text
js execution timed out; kernel reset, rerun your request
```

脚本内分阶段计时：

| 动作 | 耗时 |
|---|---|
| 新建标签页 | 0.1 s ✓ |
| 导航 | 0.2 s ✓ |
| **读取页面** | **20 s 超时** ✗ |

创建和导航秒回，只有"读取"挂。超时后内核 reset。

**把创建和读取拆成两次调用，不解决。**换个站读，同样超时。

## 已验证排除

先说走过哪几个错方向，免得重走：

- **不是工作流问题** —— 和 skill 的六步流程无关
- **不是 HTML 消息提取问题** —— 报错里不含任何页面级信息
- **不是"读取阶段的路由与回调"** —— 往这儿查了几小时，是错方向
- **不是"浏览器直连到不了闲鱼"** —— 见下

## 假说一：浏览器直连 vs CLI 代理 —— 已推翻

初次判断：Codex 浏览器直连、CLI 走 Clash 代理，两者网络环境不同。

2026-10-11 本机实测：

| 路径 | goofish 搜索页 | example.com |
|---|---|---|
| 真直连 `--noproxy '*'` | 200 / 0.05 s | 200 / 2.39 s |
| 显式 `-x 127.0.0.1:7897` | 200 / 0.05 s | 200 / 0.63 s |

**两条路都通，闲鱼 50 毫秒。** DNS 解析到国内 IP（`221.231.83.18` / `240e:979:...`）。

而且 Windows 系统代理**是开着的**：`ProxyEnable=1`、`ProxyServer=127.0.0.1:7897`、端口存活。
浏览器若吃系统设置，走的是**代理不是直连** —— 与"浏览器是直连"直接矛盾。

结论：**"直连 vs 代理"解释不了浏览器读不到页面。**

（注意：测代理必须显式 `-x`。本机环境变量里没有 `HTTP_PROXY`，而 curl 也不读
Windows 注册表的代理设置——不加 `-x` 的"代理测试"其实还是直连。）

## 未排除

- 浏览器启动时被显式指定了代理参数，指向一个不通的地址
- 浏览器进程访问 `127.0.0.1:7897` 的 loopback 被拦（沙箱 / 按进程的防火墙规则）
- **根本不是网络层** —— "读取"的实现本身在等一个永不到来的状态

## 下一步（决定性）

**① 对照组**：让浏览器打开 `example.com`，确认它能不能打开**任何**页面。

**② 关掉 Windows 系统代理**（`ProxyEnable=0`，可逆），再看浏览器读页面挂不挂：

| 结果 | 结论 |
|---|---|
| 不挂了 | 浏览器在用系统代理，但到不了 7897 |
| 还挂 | 与代理无关，网络假说整个作废 |
