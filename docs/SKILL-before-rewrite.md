# 购物决策

目标是给出一个能直接行动的判断——买哪件、为什么、还有什么没查清。这要求先把该查的查完，特别是这东西有什么已知问题；不是按关键词列一堆推荐。

语言风格：简洁，直接，切中要点，避免多余前言后语，禁止免责声明，可使用表格横评

复杂或高风险商品深入调查。篇幅可缩，支持购买判断的关键证据不能省。


## 1. 理解需求

先确认用途、预算、购买平台、新旧要求及指定型号。只问影响选择的缺失信息，提问后继续不依赖答案的研究；未回答的条件暂列为待确认。

用户给定的硬条件（预算、尺寸、必须兼容的规格）不擅自改动——有疑问就明说，不悄悄放宽或收紧。

同时检查购买设想是否适合用途，是否存在遗漏、过度配置或更合适的方案。有必要时提出，但仍按用户明确要求研究。

## 2. 定筛选标准

根据品类和场景，自行判断关键参数、使用体验、可靠性及购买陷阱。明确排除什么、为什么排除、哪些风险需要查证。

把用途转成可核查的标准，简短说明什么表现才算满足需求，而不只列规格。标准由品类和场景决定，可用数值或定性证据；影响筛选的条件未明确时，先询问或注明暂用假设。

比较相邻价位的取舍：少花钱是否已满足用途，小幅加钱是否能换来明显收益，当前价位是否存在不值得买的过渡方案。发现时直接说明差价、收益和建议；超预算方案单列，用户明确预算不可增加时不再扩展。

## 3. 搜索候选

使用现有搜索和浏览工具寻找候选，排除明显不适用项，避免重复搜索。记录型号、配置、价格和链接；价格须注明日期、平台和是否含补贴或优惠。

输出排除项以及单句简短原因。

未指定型号时，先比较有竞争力的型号方案，再筛具体商品，不因单个关键词已有结果就结束搜索。

不因已有三条可用商品就停止；先检查主要替代型号和相邻价位是否覆盖。

列表采集先读 `references/cdp-interface.md` 和对应站点配方，按配方尝试接口并在脚本内解析，只输出精简字段。工具不支持或尝试失败时才可退回普通浏览，简短说明原因；详情页可直接浏览。

已有配方（没列到的站就是没有配方）：

- 闲鱼 `goofish.com` → `references/sites/闲鱼.md`

没有配方时先普通浏览；登录与新配方处理见接口参考，不阻塞其他研究。

搜索结果可能随重载变化：分批抓取不要混算，注明抓取时间。

研究较长时先展示初步列表。主要替代方案或未知项可能改变选择时补查；不再影响选择时停止扩展，不追求穷尽市场。

## 4. 查型号问题

查证候选是否满足用户的用途。

对有竞争力的候选分别搜索缺陷、故障案例、通病、长期体验及版本差异，调查重点按品类动态决定。公开规格、性能测试和型号问题自己研究，简述查过的范围及对选择的影响，不堆搜索日志全新和二手都查型号问题。之后将这些问题简洁列出。

## 5. 验证具体商品

核对首选和备选的实际 SKU、配置、到手价、附件和售后。警惕低价引流 SKU——标价对应的是哪个具体配置。

二手另查单件损耗、维修历史和关键功能状态。

## 6. 输出

比较多个候选时做横评表，列项由品类决定；同时体现用途表现、型号问题和单件／交易差异，不用卖家描述替代型号调查，型号调查是必要的

横评覆盖实际深入调查的主要候选，不只展示最终推荐的两三项；被排除的候选也列出具体原因，重复商品合并。不为凑数量补项。

给首选前，用证据说明它怎样满足核心用途、为什么值得这个价，便宜一档牺牲什么、贵一档增加什么；没有实际价值的升级直接指出。影响结论的未知项先补查；查不到则给条件式排序（如 预算够A，不够B），不因信息更完整就优先推荐。

交付首选与备选、排除理由、主要风险及来源链接。单件状态尚待确认时，区分「优先核验」与「推荐购买」；需要实物检查的商品附简短验收项。

没有合适商品时说明原因，可建议等待、调整要求或不买。超预算方案单独列出。
