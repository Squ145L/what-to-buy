# 评估：三场景 + 无 skill 基线

按 Anthropic skill 官方指引建的（"Create evaluations BEFORE writing extensive documentation"）。
目的：把"这次感觉好不好"换成可复现的读数。此前改了十几遍、每遍只跑一次，分不清规律和运气。

## 跑法

每个场景先**不带 skill** 跑一遍（基线），再**带 skill 连跑 3 次**。
三次一起看才分得清单次波动和稳定行为。

Codex 里用 `$shopping` 触发（本机装在 `~/.codex/skills/shopping`）；不带 skill 就用同一句话、不写 `$shopping`。

## 每次记四项

1. **skill 调没调用**
2. **用没用接口**（该站有配方时）
3. **六步有没有都发生**——重点是第 4 步（查型号问题）
4. **风格**：有没有免责声明／通用提醒；是不是结论先行

## S1 简单：型号已给，仅比价

考的是**过度执行**——会不会为两个硬盘跑完六步。

```json
{
  "skills": ["shopping"],
  "query": "这两个 1TB PCIe4 固态选哪个：三星 990 Pro 和西数 SN850X，价格差不多。",
  "files": [],
  "expected_behavior": [
    "直接给结论和关键依据，不机械跑完六步",
    "不出现通用提醒或免责声明"
  ]
}
```

## S2 中等：全新、多候选、要取舍

考的是**标准由品类推出来**，以及横评表会不会退化成只看参数。

```json
{
  "skills": ["shopping"],
  "query": "300 块左右买个通勤用的无线降噪耳机，帮我挑一个。",
  "files": [],
  "expected_behavior": [
    "先给出这次判断靠哪几个量（由耳机这个品类推出来，不是通用词）",
    "横评表的列是这个品类该有的",
    "出现型号级的已知问题，而不只是参数对比",
    "不写对任何耳机都成立的通用清单"
  ]
}
```

## S3 高风险：二手、大额——反复失败的那个场景

考的是**第 4 步会不会发生**。整份 skill 反复失效的就是这里。

```json
{
  "skills": ["shopping"],
  "query": "4000 以内，闲鱼收一台二手游戏本打 FPS。",
  "files": [],
  "expected_behavior": [
    "第 2 步列出可核查的标准，并列给用户看",
    "第 4 步逐候选给出型号级问题（含通病），单件问题不混进来",
    "横评表体现型号问题，不能只有配置和价格",
    "对候选明确给「优先核验」或「推荐购买」之一，不是全部模糊处理",
    "不把型号级问题推给卖家（例如要卖家拍帧率视频）",
    "不出现免责声明"
  ]
}
```

## 怎么读

- **基线就不差** → 这个场景不需要 skill，别为它加约束
- **基线差、带 skill 三次都不行** → skill 没解决，改指令
- **带 skill 三次里时好时坏** → 是波动，改措辞没用，得换机制或换模型
